# T-035 / R-INT-02: agent design loop (2026-11-23)

Category of every analysis in the loop is labelled in the evidence: static mass properties (rigid-body), flight dynamics
(algebraic, EST inputs), FEA / SITL / gate results (stored, read not re-run), illustrative (budget and schedule arithmetic).
Status: built and demonstrated; not marked VERIFIED COMPLETE (that is the reviewer's call).

## Acceptance (R-INT-02, spec 8.2)
"Agent loop: load design, change parameter, run tests, interpret, compare, save, evidence. Thin wrapper over existing `qp/A` scripts
or the team CLI; reuse, do not duplicate. Test: one documented end-to-end run; rerun." Spec 8.2 steps 1-7 map to: stage (load),
`--set` (modify), `run_checks` (run), `interpret` + metrics (collect, interpret), `compare` (iterations), `variant_design/` (save),
`evidence.json` + `evidence.md` (evidence).

## What was built (`tools/design_loop/`)
- `cli.py`: `list-params`, `run`. No engineering logic; calls the adapter.
- `adapter_concept_a.py`: the only module that knows concept A's files; swappable for the T-034 schema (see README, same five
  functions, `--adapter adapter_<schema>`). The schema does not exist yet.
- `README.md`, `test_design_loop.py`, `.gitignore` (`runs/`), `evidence/T035-demo-pack-3p3Ah/`.
- Reused scripts, unmodified: `redesign/qp/A/proofs/gen_params_a.py`, `claims_a0..a3.py`, `redesign/proofs/build_graph.py --strict`,
  `redesign/interfaces/merge_check.py --budget redesign/qp/A/cad/model/mass_budget.json`. `tools/vtol.py` was not reused: it targets the old
  root `analysis/` design, not concept A.
- Design choice: the loop runs the claim scripts in a copy of `redesign/{proofs,interfaces,qp/A}` (files < 300 kB, about 35 MB;
  the full tree is 2 GB; the same 16 failing claims result as with a 2 MB cap). The committed tree is never written.

## Demonstration: pack 2.8 Ah -> 3.3 Ah (one real parameter)
Coupling (EST, labelled in the evidence): pack mass 270 -> 318.21 g linear in Ah; `PWR-001`, `mass.pack_g`, the itemised pack row,
then the merge_check roll-up (1640.98 -> 1689.19 g, CG x 22.000 -> 20.575 mm) added as deltas to `mass.basic_cad_kg`, `mass.cg_x_mm`.
BOM price, pack dimensions and lateral CG are NOT updated (cost claim unchanged by construction).

PASS/FAIL delta: 1 flip (CL-A-MASS-ITEM PASS -> FAIL); failing judged metrics 14 -> 15 (of 100 judged; `build_graph` counts 16 failing
claim nodes at baseline because it also lists requirement-level restatements). 16 metrics changed in all. Interpretation: the
extra 48 g of pack buys 80 s of cruise endurance and 0.6 points of static margin but takes the itemised mass over the gate
and pushes the CG toward the forward trim limit.
Rerun check: the regenerated baseline matches the committed `proofs/out/graph.json` (0 differing claim values); 7 committed files
hash-identical before and after.
