## 2. First-order trim model (shown formula, reproduces the repo plant)

Moment balance about the CG, unswept wing, thin-airfoil elevon (same terms as `a_aero.airframe`):

    delta_trim = c (CL SM - CM0) / (|x_e| CLD)         [rad, TE up]

with CL = W/(q S) = 1.881*9.81 / (0.5*1.225*17^2*0.22) = 18.45/38.9 = 0.474, c = 0.245 m, SM = 0.0761, CM0 = 0.008, |x_e| = 0.1923 m, CLD = 0.3226.
delta = 0.245 (0.474*0.0761 - 0.008) / (0.1923*0.3226) = 0.1109 rad = 6.35 deg. The plant's own trim solve (run in this task, `a_aero.airframe`, 1.881 kg, 17 m/s, CG 22.049 mm) gives 6.54 deg TE up at alpha 6.74 deg. SITL gives 7.0 deg (D-249). The model is within 0.2-0.5 deg of both. Sensitivities below are from the plant solve (script in the scratchpad, not committed); the closed form agrees.

Check against Hepperle's rule (opened, section 3.1): zero trim needs Cm = CL * sigma = 0.474*0.0761 = 0.036; we have 0.008, so 0.028 is missing; the plant reaches zero trim at CM0 about +0.037. Consistent.

## 3. Approaches found

### 3.1 Reflex / airfoil with higher Cm0 (the standard tailless answer)
- **Who:** Martin Hepperle (MH-AeroTools) design page for tailless wings; Charles River RC flying-wing article; ArduPilot forum dual-motor tailsitter thread (posts 1332-1333, palm369 and losawing).
- **Links opened:** http://www.mh-aerotools.de/airfoils/flywing1.htm ; https://charlesriverrc.org/articles/on-line-plans/albatross-asfwpp/trim-attitude-selection/ ; https://discuss.ardupilot.org/t/dual-motor-tailsitters/15302?page=66
- **Evidence it works:** Design-rule evidence, no flight trim data found. Hepperle: "Required airfoil moment: Cm = CL*·sigma", example CL 0.5, sigma 5 % gives Cm +0.025, and positive Cm is needed on an unswept wing "to avoid upward deflected flaps under trimmed flight conditions"; example airfoils E 186 / E 230 (no Cm values read). Charles River: the forward-CG wing needs reflex camber, cm/cl = xn, MH32 cm -0.057 at CL 0.8 puts CG at 32 % chord. Forum: "Tailless aircraft use reflex airfoils for that." No measured cruise elevon angle for a reflexed tailsitter was found (a Minnesota single-control-surface UAV paper and a TU Delft tailsitter wind-tunnel paper were found by search but opened as unreadable binary; their content is not used).
- **Saving for this wing (plant, 17 m/s, 1.881 kg):** trim 6.54 deg at CM0 0.008; 4.28 at 0.018; 2.01 at 0.028; -0.25 (TE down slightly) at 0.038. About 2.26 deg per +0.01 Cm0. Two ways to get it: (a) new section with Cm0 about +0.02-0.03 (saves about 2.7-4.5 deg; zero is reached near +0.037); (b) fixed trailing-edge reflex: a fixed elevon-line offset of r deg is equivalent to r deg of elevon, so r = 6.5 deg gives zero trim (same effect as a section change; costs L/D and CLmax a little, quantity —).
- **Cost to us:** (a) new airfoil: 0 g if cores are cut from a new template, but changes CLA/a0/CLmax/CD0/stall (all EST in `a_aero.py`) and the section is fixed in CAD (`s5010.dat`, `aero_s5010.py`); reruns: aero_s5010, mission/proof run_all (stall, 1.3 Vs, L/D), SITL (all T-097 cases), hover/landing not affected first-order; wing-core, spar, elevon-hinge CAD redraw, collide/assembly gates. A reflexed section is thin at the TE, which may conflict with the elevon hinge/servo-linkage geometry (—). (b) TE reflex by trimming the elevon neutral: 0 g, 0 parts; elevon mechanical zero set 6.5 deg up (linkage/servo-horn geometry change, the elevon tab and hinge check in `fwd_checks.py` rerun, flight-card step). Real headroom: stops +-20 deg then give 13.5 deg up and 26.5 deg down (before: 13.5 up, 26.5 down from trim, 20/20 from zero), so the up direction does not gain; which direction the 0.65-0.79 peak is in is not recorded here (—). Note: the metric in `fwd_sum.py` is measured from zero command, so the metric would drop by up to 6.5 deg while physical up-travel margin from trim does not change; the team should decide whether the claim's basis is stop headroom or command magnitude (this is an observation, not a pick).

### 3.2 CG and static-margin choice
- **Who:** Charles River RC (cm/cl = xn), Hepperle (sigma typical 0.02 to 0.05), forum post 1322 losawing ("the elevons neutral position will be upward" when the CG moves forward).
- **Links opened:** same three as 3.1.
- **Evidence it works:** Direct, qualitative: Hepperle sigma 0.02-0.05 versus our 0.0761 (we are above his typical range); the forum post states the CG/elevon-neutral link. No measured number for a tailsitter found.
- **Saving (plant):** 0.43 deg per mm aft (closed form: c CL dSM/(|x_e| CLD) with dSM = 1/245 per mm gives 0.44). CG +3.9 mm aft (SM 7.61 -> 6.0 %, the band floor) saves 1.7 deg (trim 4.8 deg). CG +6.4 mm (SM 5.0 %, the hard minimum) saves 2.8 deg (trim 3.7 deg). CG +5 mm gives plant trim 4.45 deg, SM 5.57 %. CG forward 5 mm: trim 8.5 deg. Pitch-use during transients scales with the same moment, so the 0.65-0.79 peak does not fall by the same amount unless the transient is trim-driven (not shown).
- **Cost to us:** 0 g if achieved by moving the battery/ballast already in the aircraft (D-249 names "a battery or ballast shift"); 0 parts; CAD scope: pack tray position and FC/pack CG table (`cad_mass.json`, MASS-GATE, `pack_trim_mm` 10 mm and `pack_trim_fwd_mm` 6 mm already exist in params); reruns: CG/SM claims (A-P), hover CG limits `cg_lo_mm`/`cg_hi_mm` in params (hover stability and thrust-moment balance, —), SITL hover and transition cases, landing (C5) because CG shifts; assembly_check/collide only if parts move. SM below 6.0 % leaves the repo's own band; SM 5 % is the hard floor with no margin for the EST NP (NP is EST; the M5 CG breadboard measures it). Hepperle's practice is lower sigma than ours, so the direction is conventional.

### 3.3 Elevon chord / area
- **Who:** no source found giving a tailsitter elevon-chord change to reduce deflection; this is derived from the repo formula. Qualitative support: Charles River RC says elevon up/down deflections produce the pitching moments; Hepperle: "larger flap deflections are needed to control an over-stabilized model" (the reverse relation: area and effectiveness set deflection).
- **Links opened:** same pages as 3.1.
- **Evidence it works:** none found as a measured case; first-order only.
- **Saving (shown):** delta scales as 1/(|x_e| CLD). Elevon span is already 0.04-0.35 m, bounded by the fin root at 0.34-0.38 m and the centreline, so only chord can change. cf/c 0.25 -> 0.30: area x1.20; thin-airfoil flap effectiveness tau = 1 - (theta - sin theta)/pi with theta = arccos(2E-1): E 0.25 -> 0.609, E 0.30 -> 0.661, ratio 1.085 (the plant uses a derated 0.5 at 0.25, so apply the ratio only); centroid 0.875c -> 0.85c moves |x_e| from 192.3 to 186.2 mm (x0.968). Net authority x1.20*1.085*0.968 = x1.26. Trim 6.54 -> 5.2 deg (saves 1.3 deg); every transient deflection also scales by 1/1.26, so 0.79 -> 0.63, 0.65 -> 0.52, 0.605 -> 0.48 of 15 deg (assumes transients are moment-driven, and the EST tau). That is the only candidate here that also lowers the peak, not only the trim.
- **Cost to us:** mass +about 20 % of elevon mass (elevon mass individually: in `cad_mass.json`, not read here, so grams —); 0 new parts; CAD scope: elevon outline, hinge line, wing-core cutout, horn/linkage and balance horn (D-187) in `redesign/qp/A/cad`; hinge moment rises with ce^2 x se (HINGE_CH in `a_aero.py`) so servo torque check `fwd_checks.py` reruns; fin/elevon clearance and rear spar position (—); reruns: roll authority (D-244/D-245 basis improves), SITL all, structures (elevon torsion hold 504.3 kPa claim), mass/CG (elevons are aft of the CG, so CG moves forward slightly, adverse for 3.2), collide/assembly gates, build guide.

### 3.4 Flight speed (AIRSPEED_CRUISE)
- **Who:** the repo plant; ArduPilot parameter page defines AIRSPEED_CRUISE.
- **Link opened:** https://ardupilot.org/plane/docs/parameters.html (AIRSPEED_CRUISE: "Target cruise airspeed in m/s in automatic throttle modes").
- **Evidence it works:** plant solve only; no external case.
- **Saving:** trim 9.19 deg at 15 m/s, 6.54 at 17, 5.61 at 18, 4.17 at 20 (trim ~ CL, so ~ 1/V^2). 17 -> 18 saves 0.9 deg, 17 -> 20 saves 2.4 deg.
- **Cost to us:** 0 g, 0 parts, one parameter (A.param line 162, now 17). But this is a performance trade: motor power and the 1.3 Vs gate (A-P6, FAIL carried at 17.74 m/s, so higher AIRSPEED_CRUISE helps that claim) against endurance/range (MISSION.md cruise numbers, —), and the TECS overshoot seen in AR-017 (20.5 m/s) is already above this. Reruns: mission gate, SITL, battery sizing claims.

### 3.5 Motor thrust-line offset / thrust vectoring in forward flight
- **Who:** ArduPilot tailsitter guide (Q_TRIM_PITCH is for "thrust line not being through the CG"; Q_OPTIONS bit 8 lets control surfaces act as "trim tabs for the motors"); parameter page (Q_TAILSIT_VFGAIN, "vectored thrust control used in forward flight for a vectored tailsitter", range 0 to 1); forum post 1329 palm369 (design keeps thrust vector through the aerodynamic centre, no downthrust).
- **Links opened:** https://ardupilot.org/plane/docs/guide-tailsitter.html ; https://ardupilot.org/plane/docs/parameters.html ; https://discuss.ardupilot.org/t/dual-motor-tailsitters/15302?page=66
- **Evidence it works:** none found of using thrust-line offset to cut cruise elevon trim. The guide uses Q_TRIM_PITCH for hover only. VFGAIN applies to a vectored tailsitter (tilting motors); concept A has fixed motors, so it does not apply (applicability as written: "—" for fixed quad).
- **Saving (shown):** needed trim moment M = |x_e| q S CLD delta = 0.1923*38.9*0.3226*0.1141 = 0.275 N m. Cruise drag D = q S CD, CD = CD0 0.0356 + CL^2/(pi e AR) = 0.0356 + 0.224/9.25 = 0.0599, D = 2.33 N (thrust at trim). A pure thrust-line offset needs dz = M/D = 0.275/2.33 = 0.118 m, about the whole prop-plane height (props at z +-0.156 m); a differential thrust between top and bottom motor pairs of M/(2*0.156) = 0.88 N, 38 % of total cruise thrust, would be needed for full removal; each 10 % of the trim moment is 0.65 deg. Whether the four-motor FW mixer in A.param (Q_TAILSIT_MOTMX 15) allows a steady pitch bias is not confirmed (—).
- **Cost to us:** motor-mount or tilt change (CAD, arm hub, collide/assembly), hover trim shift (Q_TRIM_PITCH), induced motor-efficiency loss from differential thrust; mass 0 g but substantial CAD and hover-stability reruns. Likely impractical at this magnitude (finding from the arithmetic, not a pick).

### 3.6 Incidence and twist (washout): no first-order effect on trim here
- **Who:** Hepperle: twist is computed for swept, tapered wings to bring the span load to the target; worked example AR 11, 20 deg sweep ends at -0.17 deg of twist and same incidence at root and tip; formula beta_geo = beta_req - delta_alpha0 - beta_Cm.
- **Link opened:** http://www.mh-aerotools.de/airfoils/flywing1.htm
- **Evidence:** the page does not discuss trim drag or elevons.
- **Saving:** concept A has no sweep (rectangular, c = 0.245 m), so washout produces no pitching moment about the CG by lever arm; it only shifts span load and tip stall. Whole-wing incidence changes the attitude at which L = W is met, not the moment balance, so delta_trim in the formula in section 2 is unchanged: 0 deg. Washout trimmed into the tips behaves as a Cm0 increase in effect, so it is covered numerically by 3.1 (about 2.26 deg per 0.01 equivalent Cm0); the equivalent Cm0 per degree of twist for AR 3.68 is not derived (—). "None found" of a tailsitter that cut elevon trim by twist or incidence.
- **Cost:** CAD (core templates), tip stall behaviour near CLmax (EST, no measured section CLmax), landing-stall and 1.3 Vs reruns.

### 3.7 ArduPilot settings (PTCH_TRIM_DEG, TECS pitch limits, Q_TAILSIT, Q_OPTIONS)
- **Links opened:** https://ardupilot.org/plane/docs/parameters.html ; https://ardupilot.org/plane/docs/guide-tailsitter.html ; https://ardupilot.org/plane/docs/tailsitter-tuning-guide.html
- **PTCH_TRIM_DEG** ("Offset in degrees used for in-flight pitch trimming for level flight"): sets the pitch attitude reference, not the moment balance, so the elevon still has to supply 6.5 deg to hold that alpha (trim from the formula does not contain it). Saving 0 deg. Guide: use it for fixed-wing cruise angle, Q_TRIM_PITCH for hover.
- **TECS_PITCH_MAX / TECS_PITCH_MIN** (override the PTCH_LIM pitch limits in auto throttle modes): they cap pitch demand and so bound the post-transition excursion (AR-017: pitch -4 to +9 deg). They act on the transient, not on steady trim. Value that cuts the peak below 0.60: not run (—). Cost 0 g; same lever class as the three exhausted controls tries, and a clipped pitch demand can break the 1.3 Vs and altitude limits.
- **Q_TAILSIT_* / Q_OPTIONS:** Q_TAILSIT_RAT_FW applies only until Q_TAILSIT_ANGLE (guide), so D-249 judged it does not act on the peak. Q_OPTIONS bit 8 (control surfaces as trim tabs for the motors) is already set in A.param (262400). Q_TAILSIT_VT_P_P/R_P/Y_P "are only active in VTOL modes or under Q assist" (tuning guide), so no forward-flight trim use. No setting found that changes steady trim directly. No trim-offset parameter for the elevon centre was read; SERVOn_TRIM exists in A.param (SERVO5_TRIM, SERVO6_TRIM 1500) and acts as in 3.1(b), but its description page text was not read (—).
- **Evidence it works:** none found for cutting elevon trim; the ArduPilot pages give no elevon-use criterion (also stated in AR-017).

## 5. Limits of this scout
- No source found giving a measured elevon trim angle before/after for a flying-wing tailsitter. Evidence is design rules plus the repo plant (EST aero: tau 0.5, E_OSW 0.8, NP 40.7 mm).
- Combination effects (e.g. CG +3.9 mm and cf/c 0.30 = 4.8 deg x 1/1.26 = about 3.8 deg) are linear estimates, not run.
- Transient scaling in 3.3 assumes the 0.65-0.79 peak is moment-driven; AR-017 attributes it to a TECS pitch pull-up, so this is an assumption.
- Three opened PDFs (NASA NTRS 19890011628, Minnesota, TU Delft) were unreadable binary; the USPTO patent fetch failed. Search-result summaries of them are not used as evidence.
