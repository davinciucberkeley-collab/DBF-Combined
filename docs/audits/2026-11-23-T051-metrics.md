## 4. Peak memory (measured now)

Method: `/usr/bin/time -v` is not present in this Git Bash (`ls /usr/bin/time`: no such file), so Python `psutil` 7.2.2 was used (Windows 11, Python 3.14.2). A helper (scratchpad, not in the repo) starts the command with `subprocess.Popen`, polls the process and all its children every 5 ms, sums `memory_info().rss` per poll and keeps the maximum ("peak sampled RSS, process tree"); it also reads the parent's Windows `peak_wset` at the last poll. Sampling can miss a spike shorter than 5 ms, so the sampled peak is a lower bound. stdout/stderr discarded. 3 runs each; `git status --short` shows no new file from these runs.

| Command (cwd) | rc | Wall | Peak sampled RSS, process tree | Parent peak working set (last poll) |
|---|---|---|---|---|
| `python -I tools/ledger_audit.py` (repo root), runs 1/2/3 | 0 / 0 / 0 | 0.33 / 0.09 / 0.08 s | 16.8 / 16.7 / 16.5 MB | 17.2 / 17.2 / 16.9 MB |
| `python -I proofs/run_all.py` (cwd `redesign/qp/A`; the brief's `redesign/qp/A/proofs/run_all.py` is the same script, run from its folder as T-043/T-044 do), runs 1/2/3 | 1 / 1 / 1 (expected: 12 failing claims) | 3.50 / 1.38 / 1.41 s | 40.2 / 39.6 / 40.1 MB | 26.8 / 26.8 / 26.4 MB |

Result: ledger_audit peaks at about 17 MB; run_all at about 40 MB across its process tree (about 27 MB in the parent; the rest is in child processes it spawns, not itemised). Run 1 of proofs (3.50 s) matches T-044's 3.535 s; runs 2 and 3 took 1.4 s, so run 1 included a cold file cache.
