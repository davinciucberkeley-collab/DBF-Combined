## Reasoning

Verified facts:
- Pages. DBF-Combined `index.html` is a meta-refresh and canonical link to `VTOL-Review.html`, both relative (`index.html:7-8`), plus `.nojekyll` at the root. Relative links mean it works unchanged under `/DBF-Combined/`. GitHub API (2026-11-09): DBF-Combined is public, `has_pages: false`, pushed 2026-11-09; `https://davinciucberkeley-collab.github.io/DBF-Combined/` returns 404 now; DillonVTOL `has_pages: true`, its URL returns 200.
- CI. `.github/workflows/regenerate-check.yml` triggers on push and pull_request, with `contents: read`. It rebuilds the pages and fails if committed outputs differ. It does not deploy and has no Pages step. "Deploy from a branch" Pages runs GitHub's own `pages-build-deployment` workflow, so the two do not interact. One consequence: CI keeps `VTOL-Review.html` honest, so the Pages copy is always the regenerated one.
- LFS and Pages. `.gitattributes` puts STEP/STL/F3D/SLD*/3MF/MP4/MOV/PDF/XLSX in LFS (398 files; `git lfs ls-files`). Pages serves LFS files as pointer text. The repo already handles the pages' own needs: `cad/mesh/*.stl` and `cad/drawings/DBF-DRW-001.PDF` are explicitly excluded from LFS (`.gitattributes` last two blocks). The only file/PDF link inside the published pages that points at a repo file is `cad/drawings/DBF-DRW-001.PDF` (non-LFS). Other links in the pages (`build-manual.html`, `test-plan.html`, `flight-software.html`, `templates.html`, `cad/hardware.json`, `docs/build/*.csv`, `firmware/vtol_c0.param`, `analysis/thermal/img/*.png`) are plain blobs (`git check-attr` shows no filter). Remaining PDF links are external.
- 29 MB review. It is under GitHub's 100 MB file limit and the 1 GB published-site limit; the working tree is 350 MB with real LFS files, less on Pages because pointers are tiny. Pages gzips HTML. Cost is load time (the index page already warns) and bandwidth (100 GB/month soft limit, fine for a team).
- Link inventory. README line 90 points to the DillonVTOL Pages URL and line 92 says canonical is open; README lines 138-147 list 10 claude.ai artifacts (review one is v0.3.1, "the repo file is newer"; slides are Private; five show "—" access); `docs/research/team-crosscheck.md` cites DBF-VTOL (line 3) and an artifact (line 147); README line 232 and `PROVENANCE.md` lines 15-19 list the four old repos as "kept on GitHub for their history". `CLAUDE.md:32` mentions the old repos.
- Old repo activity (API): DBF-VTOL last push 2026-11-04 (Tristan Hottier), DillonVTOL 2026-11-04, TiltWing 2026-10-20, OpenCAEModel 2026-11-02. All public, none archived. Combined repo's origin is already pushed (`git ls-remote`: main `1244ebc`).
- OpenCAEModel. Last 30 commits are 42 by "Claude" via the `claude` login, plus a few by `blavlabla` and the org account; no Student-named commits, no homepage. Snapshot at `792f0ab`, which equals its current HEAD, and the snapshot omits PE test fixtures and solved runs (`tools/opencae-studio/README.md:3-7`), so the original has content the copy lacks (GPL-3.0). `README.md:7` and `tools/opencae-studio/README.md:2` call it a general CAE tool, not C0 data.

Judgement:
- Canonical = DBF-Combined Pages, because the mentor asked for one baseline and one findable place; DillonVTOL's site would go stale on the first commit to DBF-Combined. The claude.ai artifacts are manual uploads that cannot track the repo and some are private, so they are secondary.
- Archive (not delete) the three design repos: GitHub archive keeps history, links and Pages-served files readable. DillonVTOL's Pages site stays up after archiving, so before archiving, replace its `index.html` with a redirect or notice, otherwise the old, stale review keeps being served.
- OpenCAEModel is not C0 design data, is a tool with its own history, and the snapshot is incomplete. Archiving would block its owner from pushing. Do not archive until confirmed; keep as upstream and say so in `tools/opencae-studio/README.md`.

## Risks / what would change the call
- Pages on a private repo or non-Pro org plan would 404; the repo is public so fine today. If the repo is made private, Pages fails.
- A team member still pushing to DBF-VTOL/DillonVTOL after archiving gets rejected; announce before archiving (Tristan's last DBF-VTOL push is 2026-11-04).
- 29 MB single page on phones at the flight line is slow; consider the Pages link plus a downloaded copy for field use (not a canonical-URL issue).
- If OpenCAE has an independent maintainer (ask the owner), keep developing there and re-snapshot with a version tag; if no one develops it outside this repo, archive it later and make `tools/opencae-studio` the home.
- Artifacts: if the team keeps using claude.ai artifacts as the "live" pages, they will drift again. Recommend freezing them (title suffix and a line "Superseded: see Pages URL").
