### 1.1 Width decision: the 51.4 mm drawn width counts for the block length
- The cut block is 51.4 mm wide, with a 0.3 mm gap to each guide (`subsystems/pod/fusion/pod.py` POD-009 section).
- Crushable closed-cell foam compacts in place: its plastic Poisson ratio is near zero, so it does not spread sideways
  to fill the gap. Only 51.4 mm carries the plateau stress, so A_L = 2.787e-3 m² (479 N) and over the step
  A = 2.723e-3 m² (468 N). Using 52 mm would be unconservative for the length.
- For the pack g claim I keep the full 52 mm section (486 N), the upper force. A block cut tight would load the pack
  harder, so that side stays conservative too.
- T-D5-COUPON (a coupon cut to the drawn section) checks the assumption.

On the step force:
- D2's 474 N is right. The groove floor sits below the step, so only the outboard 22 mm loses the 3 mm.
- My wave-1 459 N removed the groove width twice, so I no longer use it.
- Each ruling, worst pack (590 g), from the same formula:

| Basis | Margin |
|---|---|
| 52 mm and D2's 474 N | +1.88 mm |
| 52 mm, 459 N (D2's "conservative" variant) | +1.63 mm |
| **51.4 mm drawn width, 468 N** (adopted) | **+1.52 mm** |

## Addendum (A1 on item 6): `CL-C5-V-LAND-BROADSIDE` made heading-aware (D-152)

**What changed.** A new calc, `CALC-C5-WIND-HEADING` in `team/C5/landing_calc.py`. It is the static, pivot-stuck model
of `CALC-C5-WIND` (unchanged), extended to a heading.

- **Direction:** the lean, the 10° error and the 0.3 m/s drift all point along a lean azimuth.
- **Lean area:** the lean uses the full broadside area at every azimuth, as the 6-DOF claim does.
- **Narrow axis:** checked on its |cos az| component. The pad line is on the pod side (arm z_pad − z_cg) for azimuths within 90° of the pod face, and on the belly side (arm z_pad + z_cg) beyond.
- **Wide axis:** checked on its |sin az| component (arm y_fin, Izz).
- **Heading:** read from `P:fsw.wvane_land`, with ±`ASM-C5-HEADING-ERR` (30°). The mapping is the one the sim claim uses.

The static model can represent heading this way because each stance axis is checked on its own component. That is the
same per-axis approach as the original model. A combined-axis (corner) tip is not modelled, which leaves this check
approximate at oblique azimuths. The 6-DOF claim covers that case.

Other changes:
- `CL-C5-V-LAND-BROADSIDE` now reads the new calc. Its limit is unchanged (≥ `requirements.wind_limit_ms`).
- New information row `CL-C5-V-LAND-POD-FACE` (no limit, D-152).
- `landing_sim_claims.py`: the 6-DOF/hand ratio now reads the pod-face row, so it compares like with like (ratio 1.01).
- Re-run: `python -I team/C5/landing_calc.py` and `python -I team/C5/landing_sim_claims.py`, both exit 0. The only `FAILS` is `CL-C5-LANDINGS-PER-CARTRIDGE` (D5, unchanged). `CL-C5-SIM-INPUTS-STALE` reads 0.
