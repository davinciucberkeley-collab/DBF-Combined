# redesign/fusion - CAD framework (K09-L)

One CAD vocabulary (`fusionkit.py`) for every subsystem; the same `build(ctx)` code drives a pure-python stub
(checks, seconds), Autodesk Fusion, and later Blender (`redesign/blender/`). Connections come from
`interfaces.json` (schema: `redesign/interfaces/SCHEMA.md`). Keeper: A5 (CAD lead).

**Designers start here:** [`DATUMS.md`](DATUMS.md) (frame, attitudes, 43 named datums) ·
[`STANDARDS.md`](STANDARDS.md) (build order, naming, materials, mass, joints, hand-over checklist) ·
[`skeleton/`](skeleton/) (the K09-L reference layout, one folder per subsystem, part ids 9xx) ·
`k09kit.py` (shared helpers for this configuration).

| File | What it is |
|---|---|
| `fusionkit.py` | `Context`, `Component`, shapes (prism / revolve / loft), joints, wires, datums, keep-outs, `ctx.value(key, unit)`, NACA 4-digit helper, `Backend` interface |
| `k09kit.py` | K09-L helpers: datum sheet, airfoil `.dat` reader (+ placeholder), core/elevon lofts, tubes, fin plate and half-fins, through-core block, harness bundle bodies, transport box frame, motor/prop envelopes, prop and ground keep-outs, `pair`/`quad` mirrors, hover pose |
| `DATUMS.md` · `STANDARDS.md` | the datum sheet (table generated by `k09kit.py --datums-md`) · modelling standards |
| `modules.txt` | K09-L build order: `wing fins pod landing propulsion mechanisms power avionics harness transport` |
| `skeleton/` | K09-L reference layout at R3 (params A1-R3): 10 modules, 54 parts (50 flight + 4 transport), allocated masses (2 324 g, D-38), braced fins, 0.54 m box; `make_skeleton.py` regenerates its `interfaces.json` |
| `backends/stub_backend.py` | pure python backend used by `check.py` |
| `backends/fusion_backend.py` | Fusion API backend (cm, sketches, extrude/revolve/loft, joints, materials) - UNVERIFIED-IN-FUSION |
| `build_all.py` | discovers `redesign/subsystems/*/fusion/*.py`, builds in `modules.txt` order, prints mass and CG |
| `BuildAll/` | the folder you add in Fusion (launcher + manifest) |
| `check.py` | stub build + CAD-vs-interfaces checks; exit 1 on failure |
| `examples/` | generic test aircraft (fuselage box, wing panels + spar + hinged aileron + servo, booms + motors, battery, ESC, wires). Not a design, not K09-L |
| `tests/` | `test_framework.py` (25 tests) + `broken/` (a deliberately broken aircraft that must fail) |

## Run the checks (any machine, Python 3, no installs)

```
python -I redesign/fusion/check.py                 # real subsystems
python -I redesign/fusion/check.py --skeleton      # K09-L reference layout (passes with --strict)
python -I redesign/fusion/check.py --examples      # generic example aircraft (passes with --strict)
python -I redesign/fusion/k09kit.py --check        # DATUMS.md up to date with params.json
python -I redesign/interfaces/merge_check.py       # graph only; writes redesign/interfaces/{interfaces.json,REPORT.md}
python -I redesign/fusion/tests/test_framework.py  # 25 tests, < 1 s
```

## Build in Fusion (teammate, about 2 minutes)

1. Get the repo on your machine (`git pull`, branch `redesign/v1`).
2. Fusion: **UTILITIES** tab > **ADD-INS** panel > **Scripts and Add-Ins** (Shift+S).
3. Add the launcher once: click **+** (newer Fusion: **+ > Script or add-in from device**; older Fusion: the green
   **+** next to *My Scripts*) and pick the folder `<repo>/redesign/fusion/BuildAll`. No path to edit: the launcher
   finds the repo from its own location.
4. Select **BuildAll** > **Run**. It opens a new design, adds the **00 Datums** component, builds every subsystem
   module (or the K09-L skeleton while `redesign/subsystems/` has no modules; set `TARGET` at the top of
   `build_all.py` to `subsystems`, `skeleton` or `examples`), creates joints and wire routes, and shows a summary. The full text is in the **TEXT COMMANDS** window.
5. Optional: Preferences > General > Design > Default modeling orientation = **Z up** (our frame is z up).
6. Report back: did it run, anything in the summary marked FAIL/ERROR, screenshot. The first run is the test of
   `fusion_backend.py`. A WARN `joins rotated component` means a joint touches a part placed with
   `ctx.part(rotate=)`: Fusion aligns both joint frames, so check that part did not turn (docstring of
   `fusion_backend.py`).

Frame: metres in code, origin at the wing root LE on the chord line, x aft, y right, z up (`DATUMS.md`,
`params.json#frame`); Fusion receives cm. Each part is its own component
named `<part id> <name>` with attributes `dbf/id, status, mass_g, material`. Declared mass (interfaces.json) is
authoritative; the summary also lists Fusion's geometry x library-density mass for comparison.

## Write a subsystem module (agents)

`redesign/subsystems/<name>/fusion/<name>.py`:

```python
import k09kit as k9

def build(ctx):
    v, P = ctx.value, ctx.params           # shared: v('wing.chord_m', 'm'); local: ctx.local (<key>/params.json)
    coords, src = k9.section(ctx)          # subsystems/wing/s5010.dat (B2), else the placeholder
    c, hf = v('wing.chord_m', 'm'), k9.hinge_frac(P)
    core = ctx.part('WNG-001')             # must exist in <key>/interfaces.json (name/material/mass/status from there)
    k9.wing_core(core, coords, c, v('wing.span_m', 'm') / 2, hf, k9.span_gaps(P))
    k9.spar_y(ctx.part('WNG-002'), ctx.D('DP-SPAR'), v('wing.spar.z_m', 'm'), v('wing.spar.length_m', 'm') / 2,
              v('wing.spar.od_m', 'm'), v('wing.spar.id_m', 'm'))
    ctx.contact('E-WNG-001', 'spar bonded in slot')                        # bonded/taped/strapped edge
    y0, y1 = v('wing.elevon.inboard_y_m', 'm')
    k9.elevon(ctx.part('WNG-003'), coords, c, hf, y0, y1); k9.pair(ctx, 'WNG-003', 'WNG-005')
    ctx.revolute('E-WNG-002', 'WNG-003', 'WNG-001', at=k9.hinge_point(coords, c, hf, (y0 + y1) / 2),
                 axis='Y', limits=v('wing.elevon.deflection_deg', 'deg'))  # hinged edge
    # fins: ctx.rigid('E-FIN-009', 'FIN-005', 'FIN-003', at=ctx.D('DX-MOTOR-UR'))   fastened/clamped edge
    # harness: ctx.wire('E-HRN-001', [(...), (...)])                            electrical edge = routed wire
```

| Builder | Use for |
|---|---|
| `box(lo, hi)` | blocks, battery, electronics envelopes |
| `cylinder(axis, start, length, r)`, `tube(axis, start, length, r_out, r_in)` | spars, booms, pins |
| `prism(axis, offset, loops, depth)` | laser-cut plates, frames, hollow sections (loops: outer first, then holes) |
| `revolve(axis, center, [(a, r), ...])` | motors, spinners, wheels, pods |
| `loft(axis, [(offset, loop), ...], smooth)` | wings, tails, fairings (`fk.airfoil()` gives the loop) |
| `ctx.part(id, at=, rotate=('Z', deg))` | place / rotate a whole component |
| `ctx.mirror(src, new, plane='XZ')` | right side from left side (exact); `k9.pair` / `k9.quad` for K09-L |
| `ctx.D('DP-SPAR')`, `ctx.value(key, unit)` | datum (DATUMS.md) and params.json value, unit-checked |
| `ctx.keepout_cylinder(...)`, `ctx.keepout_halfspace(...)` | volumes no other part may enter (prop discs, hover ground) |

Rules: one component per part id; every edge you own gets exactly one registration of the right kind;
dimensions come from params files, not literals; run `check.py` before you finish and report its last line.
Keep geometry simple (envelopes for bought parts). Mark anything that depends on real Fusion behaviour
`UNVERIFIED-IN-FUSION`.

## What check.py proves, and what it does not

| Proves (stub, seconds) | Does not prove (UNVERIFIED-IN-FUSION) |
|---|---|
| every module imports and `build(ctx)` runs | that Fusion's kernel builds the sketches/lofts/revolves |
| every component has a part id, material, mass > 0, a body | that joints solve or move as intended |
| every MODELLED+ part has a component; PROPOSED ones listed as missing | that bodies do not interpenetrate (only bounding boxes are used) |
| every edge has a registration of the right kind (wire / revolute / rigid-or-contact) | real masses (declared mass is used) |
| parts of each structural edge touch (bounding boxes within 2 mm); joint origins and wire ends sit on their parts | wire bend radii, clearances, access for tools |
| no modelled group floats; all `merge_check.py` graph checks | anything about the real aircraft configuration |
| no part enters a prop keep-out or reaches the hover ground plane (bounding boxes); flight parts inside the aircraft envelope; DATUMS.md fresh | real prop-tip clearance under blade flex; interpenetration of real bodies |

`tests/test_framework.py` also runs `fusion_backend.py` end to end against a fake `adsk` module: that catches
Python mistakes in the backend, not Fusion API behaviour.

## Writing another backend (Blender)

Subclass `fusionkit.Backend` and implement `begin, component, body, joint, wire, end` (docstrings in
`fusionkit.py`). `body()` receives one of three shape kinds in component-local metres; `fusionkit.to3d(axis,
offset, (u, v))` turns plane points into 3-D points; `comp.matrix()` is the 4x4 placement. Pass the backend to
`build_all.build(backend, *build_all.roots(examples=True))`.
